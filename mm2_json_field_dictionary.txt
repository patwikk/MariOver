MM2 JSON FIELD/NUMBER DICTIONARY
=================================
Companion to mm2_tileset_dictionary.txt. That file explains the ASCII
chars used in exported text grids; this file explains the *numeric*
fields found in MM2 level JSON (toost exports, level.py/level.ksy
decodes, bcd_levels/json/*.json, etc.).

Sources: level.py / level.ksy (Kaitai struct definitions) and
mm2_viewer_json.py (OBJ_META char table).

-----------------------------------------------------------------------
2) Other per-object numeric fields
-----------------------------------------------------------------------
  x, y      Position in sub-pixels. 160 sub-pixels = 1 tile.
            tile_col = x // 160, tile_row = y // 160
  w, h      Size in tiles (direct tile counts, except Pipe — see
            mm2_viewer_json.py:obj_tile_size).
  flag      Bitfield: orientation/direction/state/color, meaning is
            object-specific (e.g. for Pipe, flag % 0x80 selects
            direction: 0x00=Right, 0x20=Left, 0x40=Up, 0x60=Down; for
            slopes, bit 0x100000 selects left vs. right slope). Not
            fully documented for every object type.
  cflag     Secondary flag bitfield (object-specific, e.g. pipe link
            color/index packing).
  ex        Extra parameter, object-specific (often unused/0).
  cid       "Connected"/companion id — index of a linked object
            (e.g. paired pipe/key-door), or -1 if unused.
  lid       Link id — used for Snake Blocks, Tracks, etc. to group
            objects that move together. -1 if unused.
  sid       Sound id — index into the sound-effect array, or -1.
  link_type Link relationship type for cid-linked objects (raw code,
            object-specific; not yet enumerated here).

-----------------------------------------------------------------------
3) ground[].id / ground[].background_id
-----------------------------------------------------------------------
Raw u8 terrain-tile graphic indices (0-255), one per ground cell.
These select a terrain sprite/variant per theme in toost's tile sheet
and are NOT yet mapped to names in this project — treat any non-zero
value as "solid ground" ('#') for ASCII purposes.

-----------------------------------------------------------------------
4) Level/world-level "_raw" enum fields
-----------------------------------------------------------------------
gamestyle_raw (Level.Gamestyle):
  12621 = SMB1   13133 = SMB3   21847 = NSMBU
  22323 = SM3DW  22349 = SMW

theme_raw (per-map Level.Map.Theme):
  0 = Overworld   1 = Underground   2 = Castle      3 = Airship
  4 = Underwater  5 = Ghost House   6 = Snow        7 = Desert
  8 = Sky         9 = Forest

autoscroll_speed_raw (Level.AutoscrollSpeed):
  0 = x1   1 = x2   2 = x3

autoscroll_type_raw (Level.Map.AutoscrollType):
  0 = None   1 = Slow   2 = Normal   3 = Fast   4 = Custom

boundary_type_raw (Level.Map.BoundaryType):
  0 = Built Above Line   1 = Built Below Line

orientation_raw (Level.Map.Orientation):
  0 = Horizontal   1 = Vertical

liquid_mode_raw (Level.Map.LiquidMode):
  0 = Static   1 = Rising/Falling   2 = Rising and Falling

liquid_speed_raw (Level.Map.LiquidSpeed):
  0 = None   1 = x1   2 = x2   3 = x3

game_version_raw (Level.GameVersion):
  0 = v1.0.0   1 = v1.0.1   2 = v1.1.0
  3 = v2.0.0   4 = v3.0.0   5 = v3.0.1   33 = unknown

clear_condition_category_raw (Level.ClearConditionCategory):
  0 = None   1 = Parts   2 = Status   3 = Actions

clear_condition_type_raw (Level.ClearCondition):
  Large enum of ~110 specific conditions (e.g. "reach the goal as
  Fire Mario", "...after defeating all Goomba", etc). See the
  ClearCondition enum in level.py for the full id -> condition list;
  toost JSON exports already include the human-readable
  "clear_condition_type" string alongside this code.

-----------------------------------------------------------------------
5) Style Power-ups (objects.id 44 and 81)
-----------------------------------------------------------------------
SMM2 reuses two object slots across game styles: the decoder always
names them "Big Mushroom" (id 44) and "SMB2 Mushroom" (id 81), but the
power-up the player actually receives -- and the sprite shown in-game --
depends on the level's gamestyle/gamestyle_raw. This is how
style-exclusive power-ups (e.g. SMB3's Super Leaf, SMW's Cape Feather)
are represented in the data: there is no separate obj_id per style,
just these two slots reinterpreted per gamestyle_raw.

  gamestyle_raw   Slot A (id 44, since v1.0.0)   Slot B (id 81, since v3.0.0)
  -------------   ---------------------------    ----------------------------
  12621  SMB1     Big Mushroom -> Mega Mario     SMB2 Mushroom -> Mini Mario
  13133  SMB3     Super Leaf -> Raccoon Mario    Frog Suit -> Frog Mario
  22349  SMW      Cape Feather -> Cape Mario     Power Balloon -> Balloon Mario
  21847  NSMBU    Propeller Mushroom -> Propeller Mario   Super Acorn -> Flying Squirrel Mario

  

Slot B (id 81) did not exist before v3.0.0 and is currently in the
extract_mm2_bcd.py skip list as "SMB2 Mushroom" (see replacements.md) --
levels containing it are skipped entirely rather than mis-converted.

mm2_viewer_json.py and mm2_json_to_ascii.py resolve the gamestyle-correct
name via STYLE_POWERUP_NAMES / resolve_obj_name() before doing OBJ_META
lookups, so e.g. an SMB3-style level's id-44 object is reported as
"Super Leaf" rather than "Big Mushroom". The ASCII char stays the same
(¶ for slot A, § for slot B) regardless of gamestyle, since the char
represents the slot, not the specific power-up.
